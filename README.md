# Requirements
- [Docker](https://docs.docker.com/engine/install/)
- [Docker Compose](https://docs.docker.com/compose/install/)
- NVIDIA Container Toolkit

## Packages

This project uses [Poetry](https://python-poetry.org/) as the package manager. 
All dependencies and their versions are defined in `pyproject.toml`.

# Environment Setup
## When using Docker
### Create docker image
```
docker build -t [image_name] .
```

### Launch Container
```
docker run  -d --gpus all -v $(pwd):/chemAutoVision [image_name]
```

## When using Docker Compose
### Launch Container
```
docker compose up -d
```

You can confirm the launched container with the following command.
```
docker ps
```

## Library Install

You can access the container with the following command.

```
docker exec -it [container_id] bash
```

After accessing the container, run the following command in the directory containing `pyproject.toml`. 

```
poetry install
```

# Dataset
All datasets used in the manuscript are generated with the following command. Dataset splitting is also performed.

[task_name] accepts one of the following: FreeSolv, ESOL, Lipo, BBBP, hERG, P-gp, CYP3A4

```
docker exec -w /chemAutoVision/src [container_id] python3 generate_data.py --task_name [task name]
```

The generated dataset is saved to `/chemAutoVision/data`.
And the generated skeletal formula images are saved `/chemAutoVision/data/images/[task_name]`

## Data splitting strategy

By default the dataset is split randomly (train/val/test = 64/16/20), which is the splitting used in the manuscript.

A Chemprop-style balanced Bemis-Murcko scaffold split is also available via `--split_type balanced_scaffold`. It retains the manuscript's train/val/test ratio of 64/16/20 and assigns all molecules sharing the same scaffold to the same subset. `--split_seed` is required for a balanced scaffold split, and the split is reproducible for a given value.

```
docker exec -w /chemAutoVision/src [container_id] python3 generate_data.py --task_name [task name] --split_type balanced_scaffold --split_seed 1
```

The outputs include the scaffold method and seed so that they never overwrite random-split artifacts or another scaffold assignment:

| Artifact | `--split_type random` (default) | `--split_type balanced_scaffold` |
| --- | --- | --- |
| Dataset | `/chemAutoVision/data/[task_name]_img.pkl` | `/chemAutoVision/data/balanced_scaffold_seed1_[task_name]_img.pkl` |
| Split CSVs | `/chemAutoVision/data/{train,val,test}_[task_name]_img.csv` | `/chemAutoVision/data/{train,val,test}_balanced_scaffold_seed1_[task_name]_img.csv` |
| Images | `/chemAutoVision/data/images/[task_name]` | `/chemAutoVision/data/images/balanced_scaffold_seed1_[task_name]` |

The images are written to a separate directory because the image file names are derived from the post-split row index, which differs between the two strategies.

When training a model on a balanced-scaffold dataset, pass the same `--split_type balanced_scaffold --split_seed 1` to the training scripts so that they load the corresponding dataset. Some scaffold distributions can make a requested fold empty; data generation fails early in that case instead of creating an unusable dataset. Seed `1` has been validated for FreeSolv.

`experiment_graph.py` accepts the same options. Its hyperparameter search,
training, prediction, and evaluation all use the selected train/val/test CSVs:

```
python3 experiment_graph.py [other options] --split_type balanced_scaffold --split_seed 1
```

When `--atom_descriptors_path` is used, every train/val/test descriptor pkl must
have a corresponding `*.meta.json` provenance sidecar. Feature-generation code
must call `utils.atom_descriptor_metadata.write_atom_descriptor_metadata()`
immediately after writing each final pkl. The graph experiment verifies the
split method and seed, subset, CSV name, molecule count, ordered-SMILES hash,
and descriptor-file hash before hyperparameter optimization starts. Missing or
legacy metadata is rejected rather than allowing an unverified experiment.

The datasets for CYP3A4 inhibition, hERG inhibition, and P-gp substrate prediction were obtained from [Han et al.](https://doi.org/10.1021/acs.jcim.4c02122). In the original study, the files labeled `valid` were used as external validation datasets. Therefore, these external datasets were excluded from the data used for model training and evaluation in this study. For each task, the corresponding `train` and `test` files were concatenated and used as the source dataset.

# Model training
Model training and evaluation are performed with following command.
The trained models generated by running the scripts below are saved to `/chemAutoVision/models`.

The trained models generated in our study are available at the following URL:

https://jstorage.app.box.com/v/ChemAutoVision

For each classification and regression task, models were trained with multiple batch-size settings. Only the best-performing model for each task is provided. The best models were selected based on ROC-AUC for classification tasks and RMSE for regression tasks.


```
# Classification task
docker exec  -w /chemAutoVision/src [container_id] \
    python3 experiment_image_classifier.py \
        --gpu 0 \
        --task_name BBBP \
        --epochs 200 \
        --model_name autokeras \
        --batch_size 8 \
        --max_trials 100 \
        --execute_data_aug \
        --seed 99

docker exec  -w /chemAutoVision/src [container_id] \
    python3 experiment_image_classifier.py \
        --gpu 0 \
        --task_name BBBP \
        --epochs 200 \
        --hp_tuning keras_tuner \
        --model_name resnet18 \
        --batch_size 8 \
        --max_trials 100 \
        --seed 99 \
        --execute_data_aug 

# Regression task
docker exec  -w /chemAutoVision/src [container_id] \
    python3 experiment_image_regressor.py \
        --gpu 0 \
        --task_name FreeSolv \
        --epochs 200 \
        --model_name autokeras \
        --batch_size 8 \
        --max_trials 100 \
        --execute_data_aug \
        --seed 99

docker exec  -w /chemAutoVision/src [container_id] \
    python3 experiment_image_regressor.py \
        --gpu 0 \
        --task_name FreeSolv \
        --epochs 200 \
        --hp_tuning keras_tuner \
        --model_name resnet18 \
        --batch_size 8 \
        --max_trials 100  \
        --seed 99 \
        --execute_data_aug 
```

# Model Prediction
The prediction results obtained by evaluating the trained models on the test data, together with the corresponding ground-truth values, are stored under `/chemAutoVision/results`.

Predictions generated by newly trained models are also stored under `/chemAutoVision/results`.

# Confirm metrics of trained model
## MLflow Tracking
Model training settings and evaluation metrics are recorded using MLflow. 
The recorded data, including parameters, metrics, and tags, is saved under `/chemAutoVision/mlruns/[experiment_id]`.

The recorded results can be viewed and compared using the [MLflow Tracking UI](https://mlflow.org/docs/latest/ml/tracking/).

You can start MLflow Tracking UI with following command.

```
docker exec -it [container_id] \
    mlflow ui \
    --host 0.0.0.0 \
    --port 5000 \
    --backend-store-uri /chemAutoVision/mlruns \
    --gunicorn-opts "--timeout 300"
```

After starting MLflow Tracking UI, open `http://localhost:5000` in your browser.
